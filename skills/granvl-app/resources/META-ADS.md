# Granvl — Meta Ads (Facebook / Instagram)

granvl's Guided Campaign Build for Meta, plus the full Meta tool reference. Read [../SKILL.md](../SKILL.md) first for the universal paid-ads invariants (everything lands PAUSED, budget caps, pause-yes / enable-never).

**Connect:** the user connects Meta from the dashboard's Ads page (Meta Ads → Connect Meta account). Open to every workspace since 2026-09-14. If a user can't connect, the agent-ETL sync recipe in SKILL.md ("Ad accounts") is the fallback.

---

## Guided Campaign Build — the walked-through flow

granvl is a **simplified ads manager**: campaign → ad set → ad, every level created **PAUSED** (activation is always the human, in Meta Ads Manager — there is deliberately no activate tool). Walk the user through the three build steps conversationally, confirming each before the write, then read the build back (step 4):

1. **`create_meta_campaign`** — ask: which ad account, campaign name, objective. Check `list_meta_pages` — if the account has no **ad identity** (Page), set it yourself with **`set_ad_identity` `{ account_id, page_id, instagram_account_id? }`** (no need to send the user to the dashboard); step 3 requires the Page. **Instagram identity:** `list_meta_pages` lists each account's `instagramAccounts` with their `@handle`, the **ad account's own Instagram list first** (`source: "ad_account"`) — that is the list Meta picks from when an ad names no Instagram account — then the identity Page's connected (`page`) and Page-backed (`page_backed`) accounts, de-duplicated by id. If no `instagramIdentity` is set and the ad account lists more than one, SET IT — otherwise Meta picks one itself, and on a shared ad account that is another brand's handle (one brand's ad once ran under a sister brand's Instagram that way). Show the user the handles and pick the one matching the brand, or ask; `instagramSuggestion` names the ad account's only account when it lists exactly one. Choose from the `ad_account` entries; a Page-list id can differ from what Meta actually uses. To set only the Instagram account, `set_ad_identity` `{ account_id, instagram_account_id }` (omit `page_id`).
2. **`create_meta_adset`** — ask: daily budget (**guardrailed** to min(workspace cap, $200/day) — if refused, relay the cap, never work around it) and target countries. Later budget edits: **`update_meta_adset_budget`** `{ account_id, campaign_id, adset_id?, daily_budget_usd, reason? }` applies at once (an ad set's own budget, or a CBO campaign's without `adset_id`) — the one place the agent writes a budget directly — inside a ceiling of **20% per 24 hours** measured from the budget at the start of the window (the workspace's lower Ad Guardrails setting wins); cuts are always allowed; repeated calls cannot ladder it up within a day. Re-record with `record_ad_entities` after. **Attribution is locked once the ad set exists** — ask the user before the first ad set on an account and pass `attribution` `{ click_days: 1|7, view_days?: 0|1, engaged_view_days?: 0|1 }`; omitted, granvl copies the account's newest ad set (the usual choice) or, with none, Meta's default 7-day click + 1-day view, and the result says which. **Another ad set like one that already runs?** Don't re-type its settings: pass **`template_adset_id`** and only what changes (see "Build from what's already running" below); the ads' copy works the same way with `create_meta_ad` `copy_from_ad_id`.
3. **`create_meta_ad`** — ask: which bucket creative(s) (`list_ad_creatives`; image **or** video — upload via `upload_ad_creative` if needed). Provide **`creative_ids`** (array) to launch one ad per creative in a single provide. Then the destination (usually their granvl lander's live URL), primary text, optional headline, and the **CTA button** (`call_to_action`, default `LEARN_MORE`). Optional extras only if the user asks: **`primary_texts` / `headlines`** with multiple entries → Meta rotates them (built-in A/B); **`enhancements`** → opt INTO specific Meta Advantage+ creative enhancements (brightness, text variations, touch-ups, …) — **default is all OFF**; only turn on what the user wants, and Meta silently drops any that don't apply to the ad. **Instagram identity is required**: if the account has none set, the call is refused (Meta would pick a connected handle itself — on a shared ad account, another brand's); set it with `set_ad_identity` (its `instagramAccounts` now include the identity Page's connected and Page-backed accounts, not only the ad account's own list), or pass `allow_no_instagram: true` only when the user wants none on purpose. **AI media**: pass `digitally_created_media: true` when the creatives are AI-made or AI-altered photorealistic media — on a political / issue / electoral campaign that sends Meta's required `authorization_category` declaration; commercial ads have no advertiser-set AI field in Meta's API, and Ads Manager has no AI-disclosure box for them either (its AI settings, Advantage+ creative translation and creative testing, are not a disclosure), so don't send the user looking for one; Meta applies its own "AI info" label, and the result says which happened. **Retries are safe**: an ad already in the ad set under the same name (from a call that timed out) is reused, not re-created — the result lists reused ids — so on a timeout, call again rather than checking Ads Manager first.

   **Video builds answer at once and finish in the background.** When the build has to upload a video (or one Meta is still processing), or more than 3 images, `create_meta_ad` returns `status: 'building'` with a `build_id` instead of waiting — Meta's video processing takes minutes, longer than an MCP tool call may run. Tell the user it is building (everything PAUSED), then **`poll_meta_ad_build` `{ build_id }`** every ~20–30s until `done` or `failed`. Never call `create_meta_ad` again for the same creatives while it builds (an identical call just returns the running build). Images-only builds of up to 3 uploads still finish inline and return `status: 'done'` with `ad_ids`.

4. **`verify_meta_build`** `{ adset_id }` — after `done`, read the ad set back **live from Meta** and walk the user through it: settings, every ad's review status, Page, Instagram handle, link + URL parameters, CTA and each video's length. Fix anything in `problems[]`; `IN_PROCESS` / `PENDING_REVIEW` is normal for a new ad (it sits in `notes[]`) — say so, don't treat it as an error.

**Tracking UTMs are automatic:** granvl puts its Meta UTM template (`utm_ad_id={{ad.id}}`, plus campaign/adset/ad name + id, placement and `site_source_name`) in the ad's **URL parameters** field (creative `url_tags`) server-side — the website URL itself stays clean, and the user sees/edits the params where Ads Manager expects them — the same params the funnel page hands out — so provide the plain lander URL. It only fills params not already present, so a URL that already has UTMs is never double-tagged.

Then tell the user: the whole chain is paused — review + activate in Ads Manager. Performance will attribute back to the exact creative(s) used.

**Save a draft instead of publishing:** if the user isn't ready to create the campaign on Meta, `save_campaign_draft` persists the in-progress build inside granvl (provide whatever `campaign` / `adset` / `ad` fields you have — same names as the create tools, all optional). It touches nothing on Meta. `list_campaign_drafts` shows saved drafts; `get_campaign_draft` reloads one to keep building (then `create_meta_*` to publish); `delete_campaign_draft` removes it. Drafts and the human wizard's "Save as draft" share the same store, so a draft saved in the UI can be finished by the agent and vice-versa.

## Meta tool reference

#### `create_meta_campaign` `{ account_id, name, objective?, creative_ids?, daily_budget_usd?, special_ad_category? }`

**Create a campaign in the user's connected Meta ad account.** Safety is server-enforced, not conventional: the campaign is **always created `PAUSED` and completely empty** (no ad sets, no ads, no budget) so it **cannot spend**; the user reviews and activates in Ads Manager. Use when the user wants to act on insights ("spin up a campaign for the winning lander") without leaving the conversation. Requires a Meta connection with **Manage access** — a `(#200)` error means the grant is read-only → tell the user to reconnect Meta with Manage access from the Ads page. `objective` defaults `OUTCOME_TRAFFIC` (provide ODAX enums like `OUTCOME_LEADS` / `OUTCOME_SALES`). The campaign appears in Granvl's Ads views after the next sync. Always tell the user the campaign is paused and where to activate it. **Money guardrails (server-enforced):** `daily_budget_usd` is capped at min(the workspace admin's guardrail, granvl's **$200/day** platform ceiling) — an over-cap request returns the cap in the error; relay it to the user, NEVER work around it. And there is **deliberately no activate/unpause tool**: activation is always the human's action in Ads Manager. **`special_ad_category`** (`NONE` default | `FINANCIAL_PRODUCTS_SERVICES` | `HOUSING` | `EMPLOYMENT` | `ISSUES_ELECTIONS_POLITICS`) is **required by Meta policy** when the ads promote a regulated vertical (loans/insurance/investing/credit, housing, jobs, or political/electoral issues) — declaring one keeps the account compliant and makes Meta auto-restrict targeting; ask the user if the offer looks financial/housing/employment/political.

#### `create_meta_adset` `{ account_id, campaign_id, name, daily_budget_usd, countries, region_keys?, excluded_countries?, excluded_region_keys?, placement_formats?, template_adset_id? }`

**Step 2**: PAUSED ad set — the targeting/optimization/budget layer. Budget clears the two-layer cap BEFORE any write (lifetime is guarded on effective daily = total ÷ flight days). Configurable: daily OR lifetime budget, optimization goal (LINK_CLICKS / LANDING_PAGE_VIEWS / REACH / IMPRESSIONS), bidding (lowest-cost or a guardrail-capped bid cap), schedule (start/end), audience (countries, age, gender), and placements (automatic Advantage+ or manual facebook/instagram/audience_network/messenger). `excluded_countries` (ISO alpha-2 codes to EXCLUDE from the targeted geo) narrows a broad `countries` set — a code **can't be in both** `countries` and `excluded_countries`. `excluded_region_keys` carves a **province / state** out of a targeted country (the Quebec case: `countries: ["CA"]` + `excluded_region_keys: ["527"]`) — the keys come from `search_meta_locations`, never hand-written, never a name or ISO code. `region_keys` does the opposite — **INCLUDES** specific provinces / states, and the ad set then targets only them (`countries` still names their country). **Special Ad Category campaigns (financial / housing / employment / politics) refuse exclusions** — Meta doesn't allow `excluded_geo_locations` there, and the server hard-fails `excluded_countries` / `excluded_region_keys` on such a campaign before any write. Narrow by **inclusion** instead: "Canada minus Quebec" on an insurance campaign = `countries: ["CA"]` + `region_keys` for the nine other provinces + three territories (resolve each with `search_meta_locations`, `type: region`, `country_code: CA`). Don't retry an exclusion with different arguments; switch to `region_keys`. The same campaigns also **refuse every audience adjustment**: age must stay 18–65+, gender `all`, no `interest_ids` — Meta fixes the audience on regulated campaigns and granvl fails the call before any write. On a Special Ad Category campaign only countries / `region_keys`, placements, schedule, budget and custom audiences are yours to set. `placement_formats` (`feeds` | `stories_reels`) is a ratio-based placement group so a creative runs only where its aspect ratio looks right (e.g. a 9:16 UGC video → `['stories_reels']`); it **takes precedence over `placements`** — omit both for automatic placements. `advantage_audience` (boolean) is Meta's Advantage+ audience: omit → on, unless you narrowed the audience with `interest_ids` / `custom_audience_ids` / `gender` / a tighter age range, in which case it defaults off so the manual picks are honoured; it is always sent explicitly because Marketing API v26.0 requires it on special-ad-category ad sets. Video ads are a later slice — for those, tell the user to refine in Ads Manager post-activation.

#### `create_meta_ad` `{ account_id, campaign_id, adset_id, creative_ids, name, link_url, primary_text, headline?, call_to_action?, primary_texts?, headlines?, enhancements?, format? }`

**Step 3 (final)**: bucket creative(s) (image or video) → Meta image hash → ad creative under the account's **ad identity** Page → PAUSED ad. Lead with **`creative_ids`** (array) — **one PAUSED ad is created per creative**, so provide several to launch multiple ads in a single provide; the singular **`creative_id`** still works for back-compat. Optional copy/CTA: **`call_to_action`** (Meta CTA enum, default `LEARN_MORE`); **`primary_texts` / `headlines`** with multiple entries → Meta rotates them (built-in A/B, `primary_text` / `headline` are the first); **`enhancements`** → opt INTO specific Meta Advantage+ creative enhancements per feature (**default all OFF** — only turn on what the user asks; Meta silently drops any that don't apply). **Ad names:** with `one_per_creative`, each ad is **named after its creative's file name**, lowercased with underscores (`slack-1080x1920.png` → `slack`, `Spring Promo VSL.mp4` → `spring_promo_vsl`), so give bucket creatives meaningful file names; **`name`** is only the fallback for a creative with no usable title. With `multi_media` / `flexible`, the one ad takes **`name` exactly as passed, capitals kept** (`Acme_W49_WalkHook_A` stays `Acme_W49_WalkHook_A`). Either way, never the campaign or ad set name. Errors are actionable (no identity set → point at Ad settings). Writes the creative↔ad linkage powering per-creative performance.

**`format`** picks how the creatives become ads:
- `one_per_creative` (default) — one PAUSED ad per creative; each ad reports on its own.
- `multi_media` — ONE ad carrying every creative in `creative_ids` (max 10) as a Meta **multi-media ad** (`media_sourcing_spec`, the current replacement for dynamic creative / the retired flexible format). Meta picks the image or video per impression. Works on any objective, including `OUTCOME_LEADS`. Tell the user the trade-off before choosing it: the ad is the reporting unit, so per-creative performance can't separate the creatives and auto-test rules can't judge them individually.
  - Reading one back: a multi-media ad keeps its videos and images in `media_sourcing_spec` (the first one also sits in `object_story_spec`), not `asset_feed_spec`, so its `asset_feed_spec` shows 0 videos even when it carries them. Read `media_sourcing_spec` before concluding a video is missing.
- `flexible` — legacy flexible ad format (`creative_asset_groups_spec`); Meta only accepts it on `OUTCOME_SALES` / `OUTCOME_APP_PROMOTION`. Prefer `multi_media`.

**Several creatives + several copies + several headlines** (the "10 creatives, 5 copies, 5 headlines" brief): default to **`format: 'multi_media'`** with `primary_texts` / `headlines` — one ad, Meta mixes every creative with every text, no ad-set flag needed, proven live. Use `one_per_creative` with the same arrays only when the user wants per-creative reporting or auto-test rules; each ad then rotates the copy on its own. Meta takes **at most 5** bodies and **5** headlines per ad (`primary_text` counts as one; extras are trimmed, primary first). Never collapse to one copy + one headline because of a Meta error — if you see "Cannot create dynamic creative ad in non-dynamic creative ad set", switch to `multi_media` or recreate the ad set with `dynamic_creative: true`; the variants stay.

**Inline or background (2026-11-05).** The call decides up front, after every check that can refuse the build (ownership, ad identity, Instagram, live lander, format caps) — those errors still come back at once:
- **Inline** — no video to upload, no video still processing on Meta, and **at most 3 image uploads** (ads already in the ad set and videos the account already holds don't count). Returns `{ status: 'done', ad_status: 'PAUSED', ad_ids, ads, reusedAdIds, instagramUserId, authorizationCategory, next_step: 'verify_meta_build', message }` — the same result as before, with `status` now naming the build and `ad_status` the ads.
- **Background** — anything else (any video upload, or 4+ images). Returns at once `{ status: 'building', build_id, adset_id, campaign_id, account_id, format, creatives, uploads: { images, videos }, already_running, next_step: 'poll_meta_ad_build', poll_after_seconds: 20, message }`; the uploads, Meta's processing and the ad writes run server-side and record each step. Poll with `poll_meta_ad_build`.

**Retrying is safe and converges.** An ad already in the ad set under the same name is reused (for a multi-media ad: the same name carrying the same creatives); a video this account already holds from an earlier build is reused instead of uploaded again; an identical call while a build is in flight returns that build (`already_running: true`). So after a `failed` or `stale` build, call `create_meta_ad` again with the **same arguments** — never rebuild the ads by hand in Ads Manager.

#### `poll_meta_ad_build` `{ build_id }`

Read-only check on a background build (polling never advances or repeats it). Returns `{ build_id, status, account_id, campaign_id, adset_id, format, progress: [{ asset_id, name, kind, ad_name, step, video_id?, image_hash?, ad_id?, error? }], steps: { total, uploaded, processing, ads_created, ads_reused, failed }, ad_ids, reused_ad_ids, created_at, updated_at, started_at, finished_at, next_step, message }`. Per-creative `step`: `queued` → `uploading` → `processing` (video on Meta, not ready yet) → `uploaded` → `creating` → `done`, or `reused` / `failed`. By `status`:
- `queued` / `uploading` / `creating` — keep polling every ~20–30s (`next_step: 'poll_meta_ad_build'`).
- `done` — adds `ads: [{ ad_id, adcreative_id, asset_id }]`, `ad_status: 'PAUSED'`, `instagram_user_id`, `authorization_category`; next `verify_meta_build`.
- `failed` — adds `error` and **`existing_ads_in_adset`** (`[{ id, name }]`, read live when the build failed; `existing_ads_source` says whether it is that read or only this build's own ids). Relay the error, fix what it names, then retry `create_meta_ad` with the same arguments — what exists is reused.
- `stale` — the row has not moved for **over 6 minutes** while not finished: the run that held it ended. Call `verify_meta_build` to see what the ad set holds, then retry `create_meta_ad` with the same arguments.

#### `verify_meta_build` `{ adset_id }`

**Reads the ad set live from Meta** — not the twice-daily sync `get_ad_entities` shows — so use it right after every build. Returns `{ source: 'meta_live', read_at, account_id, adset, campaign, ads, problems, notes, unread_fields?, message }`:
- `adset` — `name`, `status`, `effective_status`, `optimization_goal`, `billing_event`, `bid_strategy`, `bid_amount`, `budget { source: 'adset' | 'campaign', daily, lifetime, remaining }` (account currency), `attribution_spec` + `attribution` label, `start_time` / `end_time`, `promoted_object` / `pixel_id`, `is_dynamic_creative`, and `targeting { geo, excluded_geo (countries + region / city / zip keys), age_min, age_max, genders, custom_audiences, excluded_custom_audiences, interests, placements (automatic or manual platforms + positions), advantage_audience }`. `campaign` — objective, status, special ad categories, CBO budget.
- `ads[]` — `id`, `name`, `status`, `effective_status`, `review_feedback` (Meta's policy reasons), `issues`, `format` (`multi_media` | `asset_feed` | `flexible` | `single_video` | `single_image`), `page_id`, `instagram_user_id` + `instagram_username`, `link_url`, `url_tags`, `call_to_action`, `primary_texts`, `headlines`, `videos: [{ id, duration_seconds, source }]` (multi-media ads keep videos in `media_sourcing_spec`, dynamic ads in `asset_feed_spec`, single ads in `object_story_spec`; all are read), `images`, `granvl_creative_ids` (the bucket creatives granvl built it from).
- `problems[]` — `{ level, ad_id?, code, message }` for what is wrong: `no_ads`, `adset_not_live`, `no_media`, `missing_video` (granvl built it with a video Meta doesn't show), `no_link`, `missing_url_tags`, `url_tags_without_ad_id`, `no_page`, `page_not_identity`, `no_instagram`, `instagram_not_identity`, `mixed_instagram`, `disapproved`, `with_issues`. A link off granvl's domains is **not** a problem.
- `notes[]` — informational: `in_review` (`IN_PROCESS` / `PENDING_REVIEW` — normal for a new ad, video ads especially; tell the user to check back), `unread_fields` (fields Meta did not return, so not checked), `video_length_unavailable`, `truncated`.

Only this workspace's own ad sets: one in an ad account not connected here (or removed in Ads settings) is refused. Read-only, rate-limited like the other live Meta reads.

#### `attach_creatives_to_campaign` `{ account_id, campaign_id, creative_ids }`

**Attach bucket creatives to an existing Meta campaign** — the order-agnostic counterpart to `create_meta_campaign`'s `creative_ids` (campaign-first flows use this). Idempotent; re-attaching is a no-op. Attached creatives are what the ad-build step turns into actual paused ads. Refuses accounts the user removed from the workspace.

#### `list_ad_pixels` `{ account_id }`

The account's Meta pixels (id, name) for conversion-optimized ad sets. Provide a `pixel_id` + `custom_event_type` (PURCHASE / LEAD / COMPLETE_REGISTRATION / …) to `create_meta_adset` with `optimization_goal: OFFSITE_CONVERSIONS` to optimize toward real conversions instead of clicks. Read-only.

#### `list_custom_audiences` `{ account_id }`

The account's saved custom / lookalike audiences (id, name, subtype, approx size) → provide ids to `create_meta_adset` (`custom_audience_ids` / `excluded_custom_audience_ids`). Read-only.

#### `search_meta_locations` `{ query, country_code?, types? }`

Resolve a place name to Meta ad-geolocation **keys** (region / city / zip) — the id space `region_keys` (include) and `excluded_region_keys` (exclude) speak. Always check `type`: same-named places are common (Quebec is a region AND a city; you want the region). Pass `country_code` to narrow. Read-only, rate-limited.

#### `search_ad_interests` `{ query }`

Search Meta's detailed-interest taxonomy by keyword → id, name, path, approx size. Provide chosen ids to `create_meta_adset` as `interest_ids`. Read-only.

#### `list_meta_pages` `{}`

**List the Facebook Pages the workspace's Meta connections manage** (id + name only — never Page content/insights) plus each visible ad account's selected **ad identity** (the Page its ads run under — a **per-account** setting the user picks in the Ads page settings). Check the target account's identity before building ads; if none is selected, ask the user to pick one there (or set it with `set_ad_identity`). Accounts the user removed from the workspace are excluded. Read-only.

Per account: `instagramIdentity` `{ id, username, handle }` (the one set, or null) and `instagramAccounts` `[{ id, username, handle, source, sources }]` — the ad account's own list (`act_<id>/instagram_accounts`, `source: "ad_account"`) first, then the identity Page's `page` / `page_backed` accounts; an id found in several lists appears once, `sources` naming them all. `username` / `handle` are null when Meta returns no handle (the id is never shown in its place). `instagramSuggestion` is the ad account's own account when it lists exactly one, else null. When the ad account's own list can't be read (with any of the workspace's connections), `errors` says so even if the Page lists came back — don't read a Page-only list as "this is what Meta uses".

#### `set_ad_identity` `{ account_id, page_id?, instagram_account_id? }`

Sets the Page (`page_id`, verified against the Pages the workspace's connections manage; `null` clears it; omit to leave it) and/or the Instagram account (`instagram_account_id`: any id from that account's `instagramAccounts`, verified live; `null` clears it, and Meta then picks from the ad account's list). `create_meta_ad` then sends it as the ad's `instagram_user_id`. Prefer an `ad_account` entry: the reply notes when the chosen id came from a Page list while the ad account lists its own.

#### Build from what's already running: `template_adset_id` / `copy_from_ad_id`

Both read the source **live** from Meta and refuse one on an ad account this workspace hasn't connected (or removed). Explicit args always win. The reply echoes `copied_from` `{ …id, name, fields }`, `overridden` (your args that replaced a source value) and `dropped` (`[{ field, reason }]` — settings the new object does NOT get). **Read `dropped` back to the user** before going on; a stale template shows up there.

- **`create_meta_adset` `{ template_adset_id, name, …overrides }`** — only `name` is required (never copied). Copied: `campaign_id`, the budget (`lifetime_budget_usd` if the template has one, else `daily_budget_usd`; still guardrailed to min(workspace cap, $200/day), on the final number), `countries` / `region_keys` (the regions' country fills `countries`), `excluded_countries` / `excluded_region_keys`, `age_min` / `age_max`, `gender`, `custom_audience_ids` / `excluded_custom_audience_ids`, `interest_ids` (one interest group only), `advantage_audience`, `placements` plus the exact positions and device platforms, `optimization_goal`, `pixel_id` + `custom_event_type` (with `OFFSITE_CONVERSIONS`), `bid_strategy` (+ `bid_amount_usd` for a bid cap), `attribution`, a FUTURE `start_time` / `end_time`, DSA beneficiary / payor. One unit each — passing either replaces the template's pair: budget (daily / lifetime), geo (`countries` / `region_keys`; `region_keys` alone keeps the template's country), placements (`placements` / `placement_formats`). `account_id` must be the template's own (omit it). **Never copied:** status (always PAUSED), a past start / end. **Dropped and listed:** detailed targeting beyond one interest group, locales and other targeting keys, exclusions other than countries / regions, publishers other than facebook / instagram / audience_network / messenger, cost cap / ROAS bidding, billing other than impressions, non-website destinations, dynamic creative, attribution windows granvl can't set, promoted-object fields other than pixel + event. **Refused until you pass the field:** a geo of cities / zips / pins (copying the rest would widen the audience), an optimization goal granvl can't set, no ad-set budget (CBO), a lifetime budget whose end has passed.
- **`create_meta_ad` `{ copy_from_ad_id, account_id, campaign_id, adset_id, creative_ids, name, …overrides }`** — copies every primary text, headline and description, the link URL, the display link and the CTA (from the ad's asset feed when it has one, else its link / video data); `link_url` and `primary_text` stop being required. **The link is copied too** — for a new landing page pass `link_url` (the old display link is then left behind and listed in `dropped`). `primary_text` / `primary_texts` replace all the copied primary texts together; `headline` / `headlines` all the copied headlines. Media never travel: `creative_ids` still picks them. The source's URL parameters aren't copied; granvl writes its own. `descriptions` (up to 5) and `display_link` can also be passed directly.
